# 架构与维护约定

## 运行边界

Codex Remote Web 是单人浏览器工作区。Codex App Server 负责模型和工具执行；网关负责访问身份、浏览器协议边界、连接与状态协调；前端根据真实事件呈现界面。浏览器断开不拥有执行进程的生命周期。默认已有本机 daemon 时通过 Unix WebSocket 共享，否则管理独立 stdio 进程；网关停止只关闭自己的连接或自己启动的子进程，不停止共享 daemon。

## 模块

| 模块 | 职责 |
| --- | --- |
| `src/server/index.ts` | 组合配置、状态存储、原生事件与服务生命周期 |
| `src/server/config/` | 能力开关、Access 必填配置、源码/生产资源定位 |
| `src/server/auth/` | 现有本地密码机制、Access JWT 校验；两种模式显式分开 |
| `src/server/bridge/` | 共享 Unix WebSocket / 独立 stdio、JSON-RPC 关联/超时、进程内请求与执行记录 |
| `src/server/http/` | HTTP 路由、受限输入、统一认证入口及响应 |
| `src/server/realtime/` | WS/终端接入、SSE 心跳、到期和五分钟租约 |
| `src/server/files/`、`review/`、`terminal/`、`services/` | 文件边界、审查、PTY、账户、设置及自定义元数据 |
| `src/shared/` | 无 DOM 依赖的审批、Diff、输入校验和错误处理 |
| `public/` | 工作区模块、会话呈现、认证恢复及静态资源 |
| `scripts/`、`tests/`、`ops/` | 构建发布、分层验证与部署模板 |

`public/codex-surfaces.js` 和 `public/bridge-errors.js` 保留浏览器兼容导出；后端直接使用 shared 实现。开发和打包从安装目录定位资源，不依赖启动 cwd；生产入口不重建前端，独立 PTY 使用随包发布的 Node worker。

## 状态与接口

HTTP 路径、浏览器偏好和置顶/项目存储键保持兼容。前端按 threadId 隔离内容，过期导航响应不能覆盖新线程。待批请求存于网关内存并绑定连接 epoch；页面重连重新读取会话和有效请求列表。网关或原生连接更换后，旧审批不可操作，只有原生重新发送的请求才能恢复操作，不承诺原生一定重放。

普通发送、steering、HTTP 与 WS 通过 `submissions.js` 协调。UUID 绑定规范化负载摘要，状态依次为 prepared、dispatching、accepted/rejected/unknown；先保存回执再调用原生，未知结果禁止自动重发。私有回执保存原生响应，达到 10,000 条或 32 MiB 后拒绝新增，不自动丢弃去重身份。通过原生历史的 `clientId` 或迟到回执确认已接收；没有找到不等于拒绝。`host/submissions/get/list/reconcile` 提供状态查询与显式对账，列表只返回未决结果。

`delivery-queue.js` 将主会话队列保存在私有目录，版本化操作由 `host/delivery/list/mutate` 提供。每会话最多 20 条、全局最多 200 条未完成消息；保留模型、权限与输入，页面关闭后继续运行。重启、前一轮中断或不确定执行会暂停后续条目。`private-lock.js` 使用 Bun 的 `bun:sqlite` 和操作系统支持的 SQLite `BEGIN IMMEDIATE` 事务锁协调同机网关；稳定锁文件不以 PID 标记或删除旧文件作为互斥依据。仅支持本机本地文件系统，不用于跨主机、网络共享文件系统或不共享同一锁空间的容器。锁内再次确认原生空闲；Desktop 不遵守该锁，原生没有条件式空闲启动，因此仍存在最后检查竞态。Side chat 保持原生临时分支和内存队列，不进入持久提交回执或后台队列。

`POST /api/settings/developer-tools` 提供受限项目 AGENTS.md 读写预览、托管工作树生命周期、附件/专属缓存日志清理以及原生 MCP 状态清单。变更要求同源 JSON 和自定义请求头。清理预览在执行前重新校验，上传绑定与删除共用跨网关锁；队列入队先绑定附件。工作树只能在项目内专用目录创建，移除前检查占用、脏文件及忽略文件，不删除分支。占用检查包含工作树本身及其真实路径内的子目录：原生已加载会话、未完成队列、启用或正在执行的 Scheduled 均参与；符号链接别名按真实路径比较，无法识别时拒绝移除。附件上传/绑定与清理、开发工具变更也使用同一稳定 SQLite 私有锁机制。

Access 模式覆盖全部 HTTP、SSE、主 WS 与终端 WS，连接有独立租约。到期后停止发送和接受消息；新握手重新验证身份。Access 验证不改变 Codex 权限。身份接口和配置详见 [配置参考](CONFIGURATION.md)，真实撤销与部署边界见 [部署说明](deployment/CLOUDFLARE.md)。

`GET/PUT /api/settings` 仅开放审批/沙箱枚举、工作区网络布尔值、记忆生成/使用布尔值、网页搜索/摘要/回复详细程度，以及最长 16,000 字符的附加开发者指令；通过原生版本校验防止并发覆盖，不接受任意配置路径或 provider。保存使用 `reloadUserConfig: false`，不主动热更新已有会话。浏览器明确选择“Codex 配置”权限模式后省略执行权限覆盖，原生默认值对新会话生效。`GET /api/settings/storage` 仅统计文件元数据并限制时间/条目数，不跟随符号链接；`GET /api/settings/worktrees` 在允许的项目目录只读执行 `git worktree list`。归档恢复只增加 `thread/unarchive` 原生 RPC 白名单。`GET/POST /api/customize` 返回过滤后的目录和不透明标识，变更重新读取目录并通过受限原生接口处理插件安装/卸载/启停及技能启停；本机技能复制/删除由 `skill-files.js` 限制范围。所有变更要求同源 JSON、自定义请求头与显式确认，不开放任意原生 RPC。`GET /api/library` 与预览接口复用浏览及下载边界。`GET/POST /api/schedules` 使用持久存储、跨进程互斥、预先保留执行和版本校验；`scheduler.js` 通过服务端桥接执行并消费原生完成/审批事件，页面关闭不影响任务，状态不确定时暂停且不重放。文件下载和浏览器 RPC 保留原有白名单。

## 来源与发布

本项目参考 lezi-fun/codex-webui 的 MIT 许可代码与早期 WebUI 形态，当前已独立重构；Codex Remote Web 的核心是 Cloudflare Tunnel + Access 公网接入，以及围绕本机 Codex App Server 重新设计的认证、部署、状态协调和浏览器工作区。保留必要的 MIT 署名，`SOURCE_PROVENANCE.json` 记录历史参考来源和当前开发提交。公开仓库从当前源码建立独立快照；原开发仓库保留完整历史，不重写、不推送该历史。独立功能分支使用 `codex/` 前缀。当前 Git 开发身份不是未来公开维护者身份，公开前须配置实际身份及安全报告渠道。

生产发布产物从白名单生成，排除凭据、机器记录、日志、个人截图、测试和源码，同时保留许可、依赖通知、提交版本元数据及白名单内的模拟数据 README 展示图。旧 Desktop 提取资源已从当前版本替换，旧提交只保留于本地开发仓库，不进入公开快照。参见 [发布流程](RELEASING.md)。

## 本机配置控制面

`src/server/setup/` 包含受限 Cloudflare API 客户端、部署状态机、原生服务适配器和 loopback HTTP 入口。`public/remote-access.js` 在现有设置页和独立 `setup.html` 中复用；独立入口不需要启动 App Server。

一次配置依次进行资源检查、预览、Access 应用与策略创建、原生服务就绪探测、Tunnel 合并、DNS 创建和公网登录跳转检查。状态记录在用户私有配置目录；进程内互斥与磁盘锁阻止同一安装的并发部署。配置在预览后被修改时中止，不声称 Cloudflare 整体配置替换具有原子 CAS 保证。失败清理只针对本次资源；遇到被改动的托管资源保留现场，要求诊断处理。

页面重连只查询执行状态，不自动重发部署请求。配置进程异常退出后可用新的本机会话恢复服务器私有文件中已验证的 API Token，读取私有记录、诊断和清理；不自动重放未完成部署。Token 独立存储于 `management-token.json`，不混入部署记录、服务环境或浏览器存储；锁定释放内存客户端，删除凭据通过本机 CSRF 保护的接口执行。

已配置管理页直接恢复配置摘要；历史状态缺少进度数组时按空列表呈现。`configuration.js` 管理同账户中的域名、Zone、已有 Tunnel、端口和邮箱迁移，使用独立预览计划校验记录摘要、原生文件和云端状态。私有日志保留原配置和候选配置，逐步记录写入意图；提交前失败回滚，提交后显式恢复继续清理旧资源。域名改变时先建立独立的新 Access 应用，保护与 DNS 验证完成后才清理旧地址；不移除整个部署来模拟修改。路由迁移与回滚只合并所拥有的规则，专用连接器的归属独立于当前选中的 Tunnel。磁盘锁阻止本应用的并发写入，Cloudflare 外部并发修改仍可能需要人工处理。

本机 Tunnel 判断使用当前 systemd invocation 的连接器 ID，与 Cloudflare `/connections` 响应逐项匹配；无法确认时不猜测所属主机。新建模式在应用变更时创建专用 Tunnel、写入私有连接器 Token 文件并启动独立用户 unit；确认本机连接器在线后才继续发布。清理记录保留新建资源归属，但不保存连接器 Token。域名输入由共享纯函数拼接，后端以实际 Zone 名称重新校验，支持根域名 `@`，仍拒绝覆盖已有记录。


## 临时入口

`QuickTunnel` 状态机负责依赖预检、独占锁、私有目录、启动/停止与状态；完整 WebUI 提供 `openQuickOrigin` 工厂，复用同一 App Server 桥接、审批、配置和广播，避免为临时入口再启动模型进程。独立 Unix socket 监听器使用仅对该入口有效的认证适配器；公网连接无法访问本机 setup 控制面。`quick-worker.js` 作为单独 Node 监督进程解析 cloudflared 的受保护启动和在线状态，父进程 IPC 断开时清理连接器。临时目录及原生 worker 随发布包一起支持从非项目工作目录运行。

前端 `temporary-access.js` 在既有设置卡片中呈现邮箱、启动/停止、状态、地址与本地二维码。`/api/auth/status` 的 `quick-tunnel` 模式声明 SSE 不可用；实时客户端在 WS 失败时检查登录、重新握手，不降级到 SSE，也不重放 RPC。HTTP、WS 与终端共享当前 App Server 上下文；停止只关闭该入口拥有的会话。


## 会话文件与上传附件

`file-explorer.js` 提供 Files 文件树、分页/搜索、键盘导航及当前页面的文件草稿缓存；项目切换取消旧读取请求，独立保存请求可完成。`file-document.js` 管理高亮预览、CodeMirror 编辑、Markdown 段落源码范围与实时排版、保存及冲突状态；`code-editor.js` 提供语言识别、统一高亮和编辑器控件。Markdown 使用净化后的文件渲染器，不使用模型输出的内部标记清理，也不将 HTML 转回源码。文件内容不参与界面翻译。

`GET/POST /api/files/document` 使用 `files/documents.js`，仅针对浏览边界内显式项目的现有 UTF-8 文本，限制 256 KiB；额外下载根不扩展写权限。写入要求现有认证、同源 JSON 与工作区请求头。读取返回内容摘要版本和可写状态；写入重新检查真实路径、所有子级符号链接、凭据路径、文件类型/权限/硬链接数及摘要版本，同目录临时文件同步后原子替换，保留普通权限位。进程内保存检查与替换同步执行；这不提供对其他 OS 进程的文件锁，也不承诺阻止最后一次检查之后发生的外部竞争。没有创建、删除、重命名或强制覆盖接口。

`project-resources.js` 负责 Images 项目图片查询。Dock Library 由 `attachment-library.js` 展示上传记录及近期会话中明确分享的文件，不枚举服务器目录。`composer-projects.js` 提供已注册项目下拉，新增项目继续复用原文件夹选择器。

`attachments.js` 将上传分阶段写入私有 Codex home，以不透明 UUID、规范化项目目录和哈希会话关联记录元数据。`POST /api/attachments/upload` 接受同源 octet-stream；`POST /api/attachments/resolve` 校验项目后解析附件路径/关联会话；GET 列表、预览及下载共用现有 HTTP 身份验证。元数据最后发布；中断清理未发布文件。下载使用已验证文件描述符、nosniff、attachment disposition 和 sandbox CSP；图片内联仅允许识别的栅格格式。普通文件的既有路径白名单保持有效。

浏览器先保存附件草稿，发送时解析附件 ID，图片映射到原生 localImage，其他文件在文字上下文提供路径；实际调用仍走 turn/start 或 turn/steer。解析与恢复期间检查导航序列，避免发到其他会话；刷新或认证恢复不重放请求。


## 显式会话工具

`conversation-progress.js` 根据原生事件和线程快照呈现当前运行状态、具体命令/文件、耗时和最近活动时间。事件超过 20 秒没有变化时区分“服务器仍报告运行中”和“等待最新服务器状态”，成功的重复轮询不算新活动；审批、提问、断线、认证失效及执行失败分别显示。只有原生 `turn/plan/updated` 提供步骤时才展示计划完成比例，动画不代表服务器心跳。

首次打开会话的读取阶段使用不定进度动画；读取满 60 秒才显示慢加载提示与只读重试。原生桥接读取超时为 90 秒；浏览器读取等待项上限为 100 秒，为桥接错误返回留出余量，超时后转为可重试错误并清理浏览器等待项。取得历史后默认呈现最近 20 轮，按实际消息项统计渲染进度并分批让出浏览器主线程，更早历史可继续展开。导航序列隔离旧响应；读取/呈现期间保留可编辑草稿但暂停发送，不自动重发执行请求。加载期间不创建运行面板或审批卡片，不重放可能已包含在历史中的消息增量；加载结束重新读取原生最新轮次并恢复待审批状态。完成项和 diff/计划更新不单独作为开始工作的证据。完成轮次的 Show/Hide work 在详情之前，详情与最终回答独立折叠。

`composer-delivery.js` 为两个输入框提供 Steering/排队选择和可取消队列。发送请求等待确认时，发送按钮立即转圈并阻止重复提交；失败保留草稿。Steering 使用原生 `turn/steer`；队列按 FIFO 在当前轮正常完成后，通过原生 `turn/start` 发起下一轮，提交时固定模型、权限、推理强度与附件。主聊天通过 `host/delivery/list/mutate` 管理服务端持久队列，页面关闭、切换会话或刷新不会将派发责任转回浏览器；跨标签页通过事件重新读取队列，编辑、重排、取消和继续使用版本检查。服务端派发前在会话锁内核对原生活动轮与待确认提交，仍在运行则等待；直接发送或队列中存在 prepared/dispatching/unknown 回执时，后续排队消息不能通过立即发送、继续或重排绕过核对。网关重启、前轮中断/失败或未知结果使待处理项暂停，核对后仍需显式继续，不自动重发。模型、权限、推理和附件保留入队时选择。Side chat 队列仅保存在内存，关闭侧聊即清除，独立使用网关临时线程快照判断当前状态。持久主队列是本应用的后台投递机制，不是原生 App Server 队列，也不替代 Scheduled 任务。

`conversation-tools.js` 只接受 Fork 的线程/轮次以及 Goal 的受限动作、目标和预算，通过原生接口完成；不接受任意配置、状态完成标记或客户端技能路径。HTTP 变更要求同源 JSON 和 `x-workspace-request`，Access/临时访问沿用同一身份边界。输入工具目录返回不透明 ID，发送前从当前启用的原生技能重新解析，不能用失效 ID 或任意路径调用技能。Side chat 使用原生临时线程与网关内存事件快照，主聊天导航状态不参与侧边消息更新。

`composer-controls.js` 统一主对话与 Side chat 的模型、推理强度、权限菜单及原生权限转换；拒绝保留名/重复权限档案，保留托管配置的禁用状态。Side chat 首次打开时复制主对话选择，之后独立维护草稿与附件并固定项目。附件、计划与技能复用已有组件；原生临时线程不支持 Goal，菜单中禁用。侧聊内嵌原生命令/文件/权限审批与问题卡片。

`side-chats.js` 以页面随机能力键管理原生 `ephemeral` 分支，所有创建/快照/释放/转存接口使用同源 POST 保护，不开放原始注入 RPC。每个实例最多 32 份侧聊，每份最多 200 回合/约 8 MiB 内存快照，溢出时拒绝不完整转存；无保活十分钟后清理。实时事件和发送响应补齐侧聊状态，避免调用临时线程不支持的历史/恢复接口。关闭标签在接受发送后中断该回合，清理缓存并 `thread/unsubscribe`；原生内存回收遵循 App Server 自己的订阅空闲期限，不承诺立即回收。页面退出尽力释放并有超时兜底，网关断开时清空侧聊记录。

显式转存建立原生持久前缀，再用 `thread/inject_items` 导入可见侧聊消息和工具记录，图片转为文件引用。注入仅建立模型上下文，不呈现为原生轮次，也不迁移隐藏推理、运行时状态或 Goal。内容来自网关缓存，不接受客户端任意注入；模糊失败不自动重放注入。已有主对话 Fork 仍为持久化原生分支，行为不变。

普通文件预览与下载允许根目录和浏览一致：主目录、显式启动项目及额外配置的下载根。真实路径、符号链接、Codex 私有目录及凭据名限制保持有效，Review 仍使用独立根。


## 私有锁协议升级边界

新版提交、队列、附件及开发工具锁使用稳定的 SQLite sidecar。旧版基于可删除 JSON/PID 标记的锁协议与新版不能混跑；正式升级前必须停止共享同一 `CODEX_HOME` 的全部旧 WebUI 网关，再统一启动新版。不要把仍在线的公网网关与新开发网关视为可安全混用。保留提交回执、队列记录、旧锁标记及 SQLite 数据库和相关 journal/WAL/SHM sidecar；不能以手工删除、重命名或替换锁文件解除占用。OS 在进程退出时释放事务锁，恢复使用应用的校验与核对流程。参见 [升级步骤](releases/0.2.0-alpha.2.md)。本轮开发和验证不重启公网服务。
