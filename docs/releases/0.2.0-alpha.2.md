# Codex Remote Web 0.2.0-alpha.2

Codex Remote Web 的首个公开 Alpha 版本，面向单人受信任工作区。公开仓库为 [danvilig/codex-remote-web](https://github.com/danvilig/codex-remote-web)，从独立源码快照开始，早期开发历史不在公开仓库中。提供 Linux x64 和 arm64 安装包。

## 本版变化

- 桌面、平板及手机分栏交互，双侧边栏调整大小，右侧最大化，统一主题与中英文设置。
- Explorer 文件树、语法高亮、代码编辑、Markdown 预览状态编辑与冲突保护；支持会话项目目录与相对路径。
- 图片与上传文件 Library、独立附件草稿、插件/技能基本管理，以及后台 Scheduled 运行记录。
- 原生临时 Side chat 分支、共用的模型/推理/权限与附件控件，显式上下文转存；普通 Fork 仍创建持久会话。
- 工作进度与事件新鲜度、加载动画、60 秒后的历史加载重试、逐文件增删行数，以及发送中反馈。
- 提交协调与持久队列、异常提交核对和多页面同步。结果不明时暂停并保留可复制的恢复文本，禁止盲目自动重发。
- 项目 AGENTS.md 预览编辑、只读继承指令范围、托管工作树创建/移除、受限存储清理预览和只读 MCP 清单。
- Cloudflare Access 固定域名与受保护 Quick Tunnel；独立公开源码导出、历史扫描、生产依赖许可证清单和 SHA-256 校验。

完整改动见 [CHANGELOG](../../CHANGELOG.md)。具体提交、验证范围与结果见 [验收报告](0.2.0-alpha.2-acceptance.md) 及包内 `release.json`。

## 安装要求与步骤

主要平台为 Linux 原生服务，支持 x86_64（x64）和 aarch64（arm64）；Docker 为备用部署。已配置的 Codex CLI 和 Git 是工作区前提，协议基准为 Codex 0.164.0。Linux 命令沙箱仍须满足 Codex 自身对 bubblewrap/user namespace 的要求。不支持 32 位 ARM 和 Alpine/musl。

Release 提供以下形式，GitHub 另自动提供标签源码下载：

| 文件 | 用途 | 目标机器需要安装 |
| --- | --- | --- |
| `codex-remote-web-0.2.0-alpha.2-linux-x64.tar.gz` | x86_64 可执行包（推荐） | Codex CLI、Git；公网访问需要 cloudflared |
| `codex-remote-web-0.2.0-alpha.2-linux-arm64.tar.gz` | aarch64 可执行包（推荐） | 同上 |
| `codex-remote-web-0.2.0-alpha.2-deployment-linux-*.tar.gz` | 预构建 JS/静态资源部署包 | Bun 1.4.4、Node.js 24.22.2、Python 3、C/C++ 构建工具和上述工具 |
| GitHub Source code | 源码开发或自行打包 | 完整开发依赖与构建 |

**可执行包：**内置 Bun 和 Node 运行时、前端资源、对应架构的预编译终端模块，不需要现场安装依赖或编译。请保留整个解压目录，不能只复制一个可执行文件；系统仍需要 glibc 和 libstdc++ 等常规运行库。原生验收环境为 Ubuntu 24.04。

```sh
# 下载本机架构的归档及同名 .sha256 文件。
archive=codex-remote-web-0.2.0-alpha.2-linux-x64.tar.gz
# arm64 改为 codex-remote-web-0.2.0-alpha.2-linux-arm64.tar.gz
sha256sum -c "$archive.sha256"
tar -xzf "$archive"
cd codex-remote-web-0.2.0-alpha.2
CODEX_WEBUI_CWD=/path/to/your/project ./codex-remote-web
```

访问 `http://127.0.0.1:8899` 打开完整 WebUI，再进入设置 → Remote access。`./codex-remote-web setup` 只启动独立向导。支持 `--help` 和 `--version`。可选 `.env` 配置与[配置参考](../CONFIGURATION.md)一致；默认监听 loopback。

**JS 部署包：**下载 `deployment-linux-*` 及校验文件，解压后执行 `bun install --production --frozen-lockfile`，必要时 `npm rebuild node-pty`，然后 `bun run start`。源码下载需安装完整冻结依赖并执行 `bun run build`。不要把部署包和可执行包混合覆盖安装。

发布流程在两种架构的原生 GitHub runner 上验证两种实际归档，均通过后才发布。可执行包的测试主动阻止宿主机 Bun、Node、包管理器和编译器调用，覆盖异目录启动、完整页面、文件接口、真实 PTY、向导与临时连接器。包内包含运行时和依赖的许可证与来源；`dist/portable.js` 及 `runtime/REBUILD.md` 支持使用修改后的 Bun 重新构建/链接。包不含 Codex、cloudflared 或用户凭据。

固定域名需要 Cloudflare 账户、已托管域名、最小权限 API Token、cloudflared 和用户级 systemd。[本机向导](../deployment/SETUP.md)提供预览与受限管理。无域名临时访问使用支持 `--allowed-mail` 的 cloudflared 和单邮箱 OTP；临时地址随连接器结束失效，不作为永久发布域名。容器内不能自动配置宿主机 systemd；默认 Docker 镜像不含 Codex/cloudflared，不应直接公开 loopback 网关。

## 已知限制

- 当前原生协议没有条件式空闲启动或服务端幂等键。网关协调能够避免本应用内重复发起同一提交；不承诺原生 exactly-once，也不能消除 Desktop 在检查空闲后立即发起任务的竞争。
- 结果不明的发送和重启中的执行必须核对后继续。网关重连、共享 App Server 存活、原生进程退出是不同故障；原生进程退出后的运行任务不能无损恢复。
- 私有提交回执最多 10,000 条或 32 MiB，达到限制后拒绝新提交而不自动删除去重身份；需要保留记录并安排人工归档。主队列每会话最多 20 条、全局最多 200 条未完成消息。
- 主会话队列与 Scheduled 有不同的执行模型。Side chat 仍是临时分支，不提供跨刷新持久恢复，关闭侧聊会清理它的临时状态。
- 本地工作树移除只支持在本应用创建、没有已跟踪/未跟踪/忽略文件改动且未占用的目录，不删除 Git 分支。无法确认占用时拒绝移除。
- 清理仅处理过期、未绑定且未被队列引用的 WebUI 上传，以及本服务专属缓存/日志；不清理原生会话、数据库、记忆、凭据、项目或其他应用日志。移除输入框附件标记不等于删除服务端文件。
- MCP 仅提供原生状态、工具与资源清单；完整 MCP 交互、插件账户 OAuth、Sites 部署、图片生成与云端 Library 仍待开发。AGENTS 继承列表是已知文件元数据，不冒充原生服务的最终指令解析结果。
- 实际 Access 撤销时效、跨主机重启的用户服务行为、Docker Access/Tunnel 网络拓扑和 macOS 尚未完成发布验收。最长五分钟重握手不代表即时撤销已建立连接。
- Cloudflare 管理令牌以权限 600 的私有文件保存，不是加密保险箱。配置入口只应在可信本机开启；不得在仍有公网路由时切回 local 认证。

## 升级、备份与回退

保留旧安装目录、环境文件、Codex 状态、项目以及私有队列/提交状态，先在新目录安装验证。切换前停止新增执行，确认运行中任务、终端和待审批事项；查看队列与未知提交，避免升级后重发相同消息。更新服务路径后才能安排重启；安装/打包脚本不会替你重启正在运行的服务或 Tunnel。

**新旧锁协议不能混跑。** 本版提交、队列、附件及开发工具改用 Bun `bun:sqlite` 的 OS-backed SQLite 事务锁，只支持本机本地文件系统。正式升级必须先停止共享同一 `CODEX_HOME` 的全部旧 WebUI 网关，再启动新版；只停一个页面或一个入口不足以完成切换。不要与仍在运行的旧公网网关并行写入。网关全部停止后备份并保留 receipt/queue 状态、SQLite 锁数据库、相关 journal/WAL/SHM sidecar 和旧锁标记；不要手工删除、替换或重命名锁文件“解锁”。本轮本地准备没有重启公网服务或 Tunnel。

回退时恢复旧服务路径与原环境文件。不要覆盖或删除 Codex 状态、原生会话与项目。不同版本若无法解释私有执行记录，应暂停待确认提交，保留记录用于人工核对；不要通过清空私有目录“修复”队列。认证/路由变更使用 [部署恢复流程](../deployment/CLOUDFLARE.md)，不要删除共享 Tunnel 或其他 ingress。

版本标签为 `v0.2.0-alpha.2`。Release 工作流只接受对应提交已经通过 Verify 的标签，并在两种 Linux 架构的验证通过后发布预发布版本；后续升级与发布见 [发布流程](../RELEASING.md)。
