# Codex Remote Web 0.2.0-beta.1

Beta.1 combines two main changes since Alpha.3. It remains a prerelease; candidate verification does not constitute publication or complete real-desktop acceptance.

## Desktop background gateway

macOS, Windows and Linux now offer a tray/settings app for initialization, gateway start/stop/restart, remote access and diagnostics. Desktop and Web settings share themes, controls and reduced-motion-aware transitions. Closing settings or quitting the tray leaves the gateway running; logging out stops the background session. On Linux without a tray, closing settings minimizes it to the taskbar.

Install the macOS DMG, per-user Windows MSI or Ubuntu desktop DEB. In **Gateway settings**, select a project and port, check dependencies and save; then start the gateway in **Overview** and open the workspace. **Start gateway at login** is checked by default and registered on first save; uncheck it before saving if unwanted. The browser terminal is off by default. Codex CLI and Git are external prerequisites; cloudflared is needed for remote access. Desktop settings use your existing Codex account/configuration.

Desktop-managed fixed-domain and email-protected temporary access support all three platforms, including Windows. Headless automatic service deployment still requires Linux user-level systemd. Desktop processes run as the logged-in user and do not automatically take over existing services.

## Shared conversations and longer Access sessions

The default App Server mode is now `shared`; legacy `auto` also waits for the native daemon instead of starting an isolated writer. Start a compatible daemon through Codex Desktop/CLI. WebUI reconnects when it is ready, does not launch it, and never replays execution requests automatically. Stopping the gateway preserves the shared daemon and its tasks. Dedicated deployments without a daemon must explicitly set `CODEX_WEBUI_APP_SERVER_MODE=isolated`; Docker/Compose already do so. See [shared configuration](../CONFIGURATION.md#与-codex-desktop--cli-共享会话).

New fixed-domain Access applications use **30-day (`720h`) application sessions**, HttpOnly and SameSite=Lax cookies. Upgrading does not modify existing applications or browser cookies. Administrators can migrate existing applications deliberately; shorter policy/global/client sessions, revocation, logout and cleared cookies can require an earlier sign-in. Temporary-address email-code authentication is unchanged. See [migration guidance](../deployment/CLOUDFLARE.md).

## Packages, upgrade and limitations

Ten package files, each with a matching `.sha256`, are planned: macOS ARM64 DMG, Windows x64 MSI, Linux x64/ARM64 desktop DEBs, four portable CLI archives and two Linux deployment archives. `SHA256SUMS` covers those ten files. GitHub provides source downloads separately. Verify your selected file before installation and keep portable directories intact.

Requirements: macOS 15+ Apple Silicon, Windows 11 x64 with NTFS/Windows PowerShell, or glibc Linux; the desktop Linux baseline is Ubuntu 24.04 GNOME. Intel Mac, Windows ARM64 and musl are unsupported. Desktop packages are unsigned; do not disable OS protections globally. Real system trust prompts, login/logout and live mailbox authentication remain separate acceptance work; see [candidate verification](0.2.0-beta.1-acceptance.md).

Before upgrading, inspect tasks, approvals and queues, then stop every gateway sharing the same state. Back up configuration, credentials, deployment records, submission receipts, queues and SQLite databases/sidecars; do not delete locks or execution records. Install into a separate location or use the platform installer, then restart the gateway to apply the connection-mode change. A browser refresh alone is insufficient. Roll back by stopping the new gateway and restoring the previous installation/configuration while retaining execution records; isolated writers must never run concurrently against one conversation.

Before deleting the macOS app, use **Diagnostics → Stop and remove background component**. Windows MSI and Linux DEB uninstall clean owned background components while retaining user data. Cloudflare resource removal is a separate explicit action in Remote access. See [platform details](../deployment/PLATFORMS.md).

Uncertain execution is not automatically retried; native exactly-once execution and strict Desktop race prevention are not promised. Side chat remains temporary. Windows does not promise directory-entry durability across sudden power loss. Multi-host/shared-filesystem queues and automatic production migration are outside this release.

## 中文

Beta.1 相比 Alpha.3 包含两个主要部分，仍为预发布候选，准备候选不等于已公开发布或完成真实桌面验收。

**后台网关与桌面设置：** macOS DMG、Windows 当前用户 MSI、Linux 桌面 DEB 提供统一的初始化、托盘、启停/重启、远程访问与诊断页面。桌面与 Web 设置协调主题和控件，动效遵循减少动态效果偏好。关闭窗口或退出托盘后网关继续运行，注销后停止；Linux 无托盘时最小化到任务栏。在“网关设置”选择项目和端口、检测依赖并保存，再从“概览”启动。“登录时启动网关”默认勾选，首次保存时注册，不需要时请先取消勾选；网页终端默认关闭。沿用现有 Codex 账户与配置，需自行安装 Codex CLI、Git，公网还需 cloudflared。三端桌面均支持托管固定域名及受邮箱保护的临时访问，Windows 也包含在内。无桌面自动部署仍使用 Linux 用户级 systemd，不自动接管旧服务。

**共享会话与登录时长：** 默认连接共享 Codex daemon，旧值 `auto` 也会等待，不因启动顺序回退独立写入进程。先通过 Codex Desktop/CLI 启动兼容 daemon；WebUI 不代为启动它，服务就绪后重连，不重放执行请求，停止网关不停止 daemon 或其任务。没有 daemon 的专用部署须显式选择 `CODEX_WEBUI_APP_SERVER_MODE=isolated`，Docker/Compose 已显式设置。新建固定域名 Access 应用采用 30 天（`720h`）应用会话及 HttpOnly、SameSite=Lax Cookie；升级不会修改已有应用或 Cookie，需管理员按[迁移说明](../deployment/CLOUDFLARE.md)另行调整。较短会话设置、撤销、退出或清除 Cookie 仍可提前要求登录，临时地址认证不变。

计划提供十个安装/归档文件及各自校验文件和汇总 `SHA256SUMS`：DMG、MSI、两种架构 DEB、四种 CLI 便携包、两种 Linux 部署包。平台要求和未签名限制同上；不支持 Intel Mac、Windows ARM64 或 musl。安装前核对校验和，保留完整便携目录。

升级前核对任务、审批和队列，停止共享状态的所有旧网关，备份并保留配置、凭据、部署记录、回执、队列及 SQLite 数据库/sidecar；不要删除锁和执行记录。安装后重启网关切换连接模式，仅刷新网页无效；回退先停新版，再恢复旧安装和配置，保留执行记录，不得混跑独立写入进程。macOS 删除应用前从“诊断”移除后台组件；Windows/Linux 卸载清理自有后台组件并保留数据，云端资源另行移除。

[候选验证记录](0.2.0-beta.1-acceptance.md)区分自动化检查与待完成的真实系统信任提示、登录/注销和公网邮箱认证。未知执行不自动重试，不承诺原生 exactly-once 或严格消除 Desktop 并发竞态；Side chat 仍为临时会话。Windows 突然断电的目录项持久性、跨主机共享状态和自动迁移生产部署不在保证范围内。
