# Beta.1 candidate verification / 候选验证记录

Scope: the integrated desktop gateway, shared-session/Access changes and bilingual documentation from PRs #8, #9 and #10, plus Beta.1 version/release preparation. This document is an evidence index, not a claim that publication or manual platform acceptance is complete.

## Automated evidence

- The preparation PR records exact local commands/results and links to final Verify, PR policy and native-platform CI for its checked commit. Use its current checks; a passing feature run does not replace integrated candidate verification.
- Verify runs dependency audit, build/check, unit tests, browser execution/queue/workspace regressions, WebKit, performance, Access, setup, temporary access, project-root, production and portable archive checks, plus desktop, Docker and source/candidate checks in CI. Verify and candidate CI provision checksum-pinned cloudflared and require its real offline CLI validation; missing binaries fail those gates. Ordinary local verification can still report SKIP when cloudflared is absent and not explicitly required.
- Native CI builds and tests actual Linux x64/ARM64 DEBs, macOS ARM64 DMG and Windows x64 MSI, together with CLI/deployment archives. Desktop tests exercise window sandbox/preload isolation, tray exit with gateway continuity, reconnection and stop using synthetic fixtures. They do not establish real user login/logout behavior.
- Fixtures use disposable projects, simulated App Server/Cloudflare and test keys. They do not call paid models, use personal credentials, mutate Cloudflare or restart production.

## Manual acceptance still required

- Real macOS/Windows/Linux desktop installation, OS trust prompts and normal mouse/keyboard operation, including actual logout/login startup and uninstall on maintained machines.
- Actual Cloudflare email login, 30-day session persistence, revocation timing and network switching. Existing applications require deliberate migration; the application setting alone does not guarantee uninterrupted 30-day access.
- Actual phone/tablet/public-network use for this candidate. Simulated responsive layouts and WebKit checks are not physical-device acceptance.

No new manual acceptance for those items is claimed here. Existing Alpha-era live results are historical and do not establish Beta.1 acceptance. Native exactly-once execution, strict Desktop race prevention, Windows directory fsync and multi-host shared state remain outside the guarantee.

For this repair iteration, the maintainer explicitly deferred additional native/manual validation. The readiness verdict covers the remaining automated checks only. An earlier Linux simulation exposed a direct-child-only cleanup gap in the Windows branch. The repair now places the hidden helper in a non-breakaway, kill-on-close Job before starting Codex; tools inherit ownership, and setup failures prevent an unsupervised launch. Offline compilation, protocol and lifecycle checks are distinct from additional native tool-descendant acceptance, which remains deferred. Normal native package CI still exercises the packaged gateway lifecycle. Shared-daemon tasks intentionally remain independent of gateway lifetime.

## Publication gate

Promote the reviewed release branch to protected `main` through a PR with a merge commit. The exact resulting main commit must pass main-push Verify before a separately authorized `v0.2.0-beta.1` tag/publication. Keep existing tags and assets unchanged; validate all ten package hashes before uploading. Candidate artifacts do not authorize production migration.

维护者已明确暂缓本轮新增的原生/人工验证，就绪结论仅覆盖其余自动化检查。此前 Linux 模拟暴露了 Windows 分支仅清理直接子进程的代码缺口。本轮改为先将隐藏辅助进程加入不允许 breakaway、关闭句柄即清理的 Job，再启动继承归属的 Codex；建立失败时不允许无监督启动。离线编译、协议与生命周期回归不等于新增原生后代进程专项验收，后者仍暂缓；常规原生打包 CI 继续检查实际网关生命周期。共享 daemon 的任务按设计独立于网关生命周期。
